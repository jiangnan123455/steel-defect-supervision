# Web 展示页设计系统

钢材缺陷检测系统的对外展示页（`site/index.html`）。本文说明四层视觉基建怎么搭、
按什么顺序搭、彼此的边界在哪，以及哪些做法被明确排除、为什么。

页面用真实数据：NEU-DET 六类缺陷、1797 张图、测试集 270 张、
Precision 0.659 / Recall 0.702 / mAP@0.5 0.628、区域误差 1.55 个、热点命中 0.563。

---

## 一、四层的分工

| 层 | 承担什么 | 不承担什么 |
|---|---|---|
| 1 CSS 材质 | 底色、柔光、阴影、边线、字号节奏 | 不做装饰性图案，不做玻璃模糊 |
| 2 动效 | 指针反馈、入场、一个滚动时刻 | 不做每节渐入，不做视差，不做轮播 |
| 3 3D 氛围 | 一处实时点阵地形（WebGL） | 不做全页背景，不做第二个 canvas |
| 4 组件系统 | token、按钮、卡片、UI 片段、状态 | 不做第三套按钮或第二套圆角 |

四层的顺序不是并列的，是**逐层收窄**：材质定基调 → 动效定节奏 → 3D 定记忆点 →
组件把前三者收进可复用的规则里。反过来说，组件层是前三层的约束器：它决定了材质只能用
哪几个 token、动效只能用哪几个时机、3D 只能出现在哪个槽位。

---

## 二、第 1 层：CSS 材质

### 做了什么

| 手段 | 落点 | 具体值 |
|---|---|---|
| 暖石灰底 | 全页主底 | `#dfdedb`，不是纯白，带一点车间地面的灰度 |
| 双层径向柔光 | 首屏右侧拼贴框 | 左上 76% 白提亮 + 右下 82% 底色混主色，透明度收到 72% |
| 极轻阴影 | 卡片、窗口、浮卡 | `0 1px 0` 内高光 + `0 18px 40px -22px` 外投影，负扩散让阴影只落在下沿 |
| 细边线 | 卡片、表格、窗口 | `currentColor` 的 12–16%，不用纯灰 |
| 哑光面板 | 三步卡片的面板 | `ground-bg 26% + 页面底`，叠一层 70% 白径向 |
| 数字对齐 | 所有数值 | `font-variant-numeric: tabular-nums` + DM Mono，等宽不跳动 |

### 明确没做：毛玻璃

需求里提到毛玻璃。**没有做，因为它在这个页面上是错的**：

- `backdrop-filter` 会让底下的检测图透上来，图上的文字对比度随图变化，无法保证 4.5:1；
- 一批质检界面（Linear、Vercel、x.ai）都不用玻璃，用的是**哑光分层 + 一条细边**；
- 玻璃在浅色工业底上读起来像"移动端卡片"，不像仪表。

替代方案是**哑光三层**：页面底（暖灰）→ 卡片（白）→ 面板（暖灰带柔光）。
三层之间只用 1 个明度台阶 + 1 条 12% 边线，不用模糊、不用半透明。

### 颗粒纹理的归宿

需求里提到颗粒。单独铺一层噪点会变成装饰，而且会吃掉对比度。
这一页把"颗粒"交给第 3 层的点阵地形——它本身就是由几万个点构成的表面，
放大看是颗粒，退后看是纹理。这样颗粒有信息含义，不是背景噪点。

## 三、第 2 层：动效

### 分三档，各有各的职责

| 档位 | 触发 | 时长 | 用在哪 |
|---|---|---|---|
| 微交互 | hover / press / focus | 150–320ms | 按钮、链接卡、导航、输入框 |
| 入场 | 加载一次 | 700ms | 只有首屏（`data-enter`） |
| 页面时刻 | 滚动 | 由滚动位置驱动 | 只有一处（`#claim` 大字聚合） |

### 具体做了

- **按钮**：hover 时上移 2px 并加深，press 时回落到 0 并缩 0.98；箭头随 hover 前移 2px。
- **链接卡**：整卡上浮 2px，卡内图片放大 1.02–1.03。
- **首屏**：标题、正文、按钮、右侧窗口按 0 / 80 / 160 / 240ms 依次入场，只跑一次。
- **大字时刻**：`#claim` 的"每张差 1.55 个"随滚动上升时，单字从散开状态逐个归位，
  到达屏幕中线上方时已经整齐。
- **数字**：首屏窗口里的队列行有一次性错位入场（`data-ly-steps`），之后静止。

### 明确没做

- **每节滚动渐入**：需求里提到"滚动渐入"。技能规则里这是硬禁止——
  每个 section 都淡入会让长页面变成幻灯片，且用户快速滚动时看到的是空白。
  只保留首屏入场和一处大字时刻，其余全部静止。
- **视差背景**：文字视差会破坏阅读，图片视差在单屏 section 里没有行程可走。
- **轮播 / 定时切换 / 倾斜**：同上，一律不做。

## 四、第 3 层：3D 氛围

### 是什么

`#scan` 里的**点阵地形**：约 1.2 万个点在 GPU 上按噪声场起伏，带方向光和边缘高光，
缓慢起伏。它不是图片，是实时绘制的 WebGL canvas。

### 为什么是它

这一节讲的是"缺陷只占几十个像素，模型学的是纹理走向"。
点阵地形的形态正好是**扫描得到的表面**：远看是起伏的钢面，近看是一个个采样点。
它承担的是概念，不是装饰。

### 约束（关键）

一页**只能有一个**实时效果。这是硬约束，原因是性能与注意力：

- 多个 canvas 会互相抢 GPU 和滚动帧率；
- 多个动态背景会让"重点"消失，用户不知道该看哪。

所以：

| 位置 | 有没有 3D |
|---|---|
| 首屏 | 没有（用真实检测窗口，产品自己就是画面） |
| `#app` | 没有（应用窗口是主体） |
| `#method` / `#zones` | 没有（数据是主体） |
| `#scan` | **有，唯一一处** |
| `#evidence` / `#claim` / `#faq` | 没有（深色数据、大字、问答，各有各的视觉） |

### 降级

- `prefers-reduced-motion` → 静止一帧；
- WebGL 不可用 → 同色 CSS 兜底；
- 离开视口或切到后台 → 停止绘制；
- 像素比上限 1.75，粒子按半分辨率绘制。

### 关于"Three.js"

页面没有引入 Three.js 库。效果是用原生 WebGL 着色器画的，**省掉了 600KB 依赖**，
首屏不必等一个 3D 库下载完才能渲染。视觉结果与 Three.js 粒子场同类，
但加载成本低一个数量级。答辩时如果要讲"用了 Three.js"，说"用了 WebGL 实时渲染"更准确。

## 五、第 4 层：组件系统

### token

```
颜色   主底 #dfdedb · 面板 #d3d2ce · 墨色 #26251e · 次墨 #5a5850 · 强调 #2456d6
字体   Instrument Sans（拉丁）+ 系统中文字体栈；DM Mono 只用于数字与代码
字号   h1 64 · h2 48 · h3 20 · 正文 16 · 小字 14 · 标签 13
间距   4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96
圆角   卡片 12 · 控件 8 · 徽章 999
阴影   内高光 1px + 下沿负扩散投影
```

强调色只有一个：**蓝图蓝 `#2456d6`**。红色不出现在界面里，
因为红色在这套系统里的唯一含义是"缺陷"——检测框的红色必须独占这个语义。

### 组件清单

| 类别 | 组件 | 状态 |
|---|---|---|
| 按钮 | 主按钮（实心胶囊）、次按钮（描边胶囊）、大号收尾按钮 | default / hover / press / focus / disabled |
| 导航 | 中置导航 + 移动端抽屉 + 当前页标记 | default / hover / 打开 / 滚动后固定 |
| 卡片 | 三步卡、开卡（无边框）、数据卡 | default / hover（仅可点卡片上浮） |
| 数据展示 | 九宫格 tile、指标表、队列窗口、检测窗格 | 静态 + 空态（`—` / `排队`） |
| 反馈 | 状态徽章（已检 / 待复判 / 低置信）、错误行内提示 | 四色语义 |
| 空态 | 首屏三步引导、无缺陷时的提示 | 文案 + 图形 |

### 页面级片段

检测台窗口、九宫格 tile、队列列表、滑块读数、上传槽——这些都按真实产品的
字号与密度做（13px 正文 / 12px 元信息 / 11px 标签），不是"示意图"。
数字来自真实推理：`patches_109` 的 3 个框置信度 0.904 / 0.726 / 0.690，
九宫格归属中央 / 左下 / 右中。

## 六、构建顺序（为什么是这个顺序）

```
1. 定 kind 与主行动      → 软件产品页；主行动"看检测结果"
2. 抽 hero 与配色        → 拼贴首屏 + 暖石灰/蓝图蓝
3. 定字号与间距 token    → 所有后续尺寸从这里取
4. 搭骨架（section 高度）→ 一屏一节，先把 9 屏的高度钉死
5. 填真实内容与真实图    → 检测窗口、九宫格、指标表
6. 加材质（柔光/阴影）   → 只在已定稿的骨架内加，不改变高度
7. 加动效                → 先微交互，再入场，最后大字时刻
8. 加 3D                 → 最后，且只进预留的那一个槽位
9. 跑检查器              → 1440 下逐项过；不合格回退到对应层
```

关键点：**先钉高度，再加视觉**。
材质和动效都会影响渲染尺寸，如果在骨架没定时就加阴影和动画，
section 高度会来回变，一屏一节的规则永远调不平。

同理，3D 放最后：它的 canvas 尺寸、像素比、帧率都会影响布局与性能，
必须在一个已经稳定的骨架里安装。

## 七、交付范围

### 包含

- `site/index.html`：单页，9 屏，1440 桌面视图
- `site/assets/`：设计系统、组件库、动效层、着色器、本地字体、真实检测图
- 桌面宽度 **1440 / 1024** 已校准

### 不包含（按你的要求）

- **移动端适配不做**。页面在窄屏下仍能渲染（CSS 是响应式的），
  但不保证 390 / 768 下的断行、行高、屏高符合规范。
- 不做多语言、不做后台、不做表单提交（页面无表单）。
- 不做暗色主题（这套配色的暗色版需要重新调全部对比度，不在本次范围）。

---

## 八、关键实现约束

| 约束 | 原因 |
|---|---|
| 一屏一节，每节 900px | 滚动时每屏只读一件事，答辩演示不出现半截内容 |
| 一个实时效果，最多两处滚动时刻 | 多个动态背景互相抢注意力，也拖帧率 |
| 禁止毛玻璃 / backdrop-filter | 检测图在下面，模糊后文字对比度不可控 |
| 禁止每节滚动渐入 | 快速滚动会看到空白，长页变幻灯片 |
| 强调色只有一个，红色专属缺陷 | 红色在质检语境里等于告警，做品牌色会和标注框抢语义 |
| 所有数字等宽 | 指标表里 0.628 与 0.659 必须对齐，否则读数会跳 |
| 图片全部真实 | 检测图来自最终权重的真实推理，不用示意图 |
| 字体本地托管 | 答辩现场断网也能正常显示，不等 Google Fonts |
