# UI 统一改造方案与改动范围说明

> 改造日期：2026-11-24
> 设计引擎：ui-ux-pro-max（本地离线设计系统生成器 + 人工校正）
> 约束：**不改变任何业务逻辑与功能**，仅调整界面呈现

---

## 1. 设计依据与校正说明

### 1.1 引擎推导结果

`python scripts/engine.py generate "industrial quality inspection dashboard for steel surface defect detection"` 的结论：

| 维度 | 引擎推荐 |
|---|---|
| 产品类型 | Dashboard / Admin（置信分 8.968） |
| 页面结构 | Sidebar nav → KPI row → charts → data table → actions |
| 风格 | Data / Dashboard（备选 Material Design、Industrial / Utility） |
| 字体 | Inter |
| 反模式 | 信息过载、无空状态、低对比度数据 |

### 1.2 人工校正（重要）

引擎同时推荐了 **Calm Analogous 001** 调色板，主色为红棕色 `#A74444`。该方案在本项目**不可直接采用**：

- 红色在质检语境中天然表示「缺陷 / 报警 / 不合格」，作为品牌主色会与缺陷标注框产生语义冲突；
- 违反引擎自身的 P0 规则 UX-037（`green=success, red=error, amber=warn, blue=info`）。

因此校正为：**工业冷蓝 `#185FA5` 作唯一品牌强调色，红色严格保留给缺陷与告警语义**。这符合 UX-039（单一品牌强调色，克制使用）。

## 2. 设计系统（Design Tokens）

全部 token 定义在 `src/ui_theme.py` 的 `THEME_CSS`，页面通过 `inject_theme()` 一次注入。

### 2.1 色彩

| 角色 | 色值 | 用途 |
|---|---|---|
| `--brand` | `#185FA5` | 主操作按钮、选中态、图表主色 |
| `--brand-strong` | `#134E86` | 主按钮 hover |
| `--brand-soft` | `#EAF2FB` | 品牌浅底、选中背景 |
| `--accent` | `#0F6E56` | 少量强调（备用） |
| `--bg` | `#F6F8FB` | 页面底色（冷灰白） |
| `--surface` | `#FFFFFF` | 卡片、侧栏 |
| `--surface-2` | `#EFF3F8` | 次级填充、规则说明条 |
| `--border` | `#DFE6EF` | 卡片与控件描边 |
| `--text` | `#14202E` | 正文与标题 |
| `--text-2` | `#5B6B7C` | 次要说明、图注 |
| `--text-3` | `#8A98A8` | 提示文字、图例 |
| `--success` | `#15803D` | 模型就绪、热点结论 |
| `--warning` | `#B45309` | 未检出提示、中置信度 |
| `--danger` | `#B91C1C` | 缺陷框、低置信、热点区域、错误 |
| `--info` | `#185FA5` | 一般性信息提示 |

置信度语义分级（表格与图例共用）：高 ≥ 0.70 / 中 0.40–0.69 / 低 < 0.40。

### 2.2 字体

```
--font-sans: "Inter", -apple-system, "Segoe UI", "Microsoft YaHei",
             "PingFang SC", "Noto Sans SC", sans-serif
--font-mono: "JetBrains Mono", Consolas, monospace
```

| 层级 | 字号 | 字重 | 行高 |
|---|---:|---:|---:|
| 页面标题 h1 | 25px | 600 | 1.45 |
| 分区标题 h2 | 18px | 600 | 1.5 |
| 区块标题 h3 | 15px | 600 | 1.5 |
| 正文 | 14px | 400 | 1.65 |
| 图注 / 说明 | 12px | 400 | 1.6 |
| KPI 数值 | 30px | 600 | 1.1（tabular-nums） |

数字统一使用 `font-variant-numeric: tabular-nums`，保证表格与指标纵向对齐。

### 2.3 间距、圆角、阴影

| Token | 值 | 用途 |
|---|---|---|
| `--space-1…6` | 4 / 8 / 12 / 16 / 24 / 32 px | 8px 基准间距体系 |
| `--radius-card` | 12px | 卡片、图表容器、图片 |
| `--radius-control` | 8px | 按钮、输入框、tile |
| 胶囊 | 999px | 状态徽章、热点标记 |
| `--shadow-card` | `0 1px 2px rgba(20,32,46,.06), 0 1px 3px rgba(20,32,46,.04)` | 极轻投影，不做重阴影 |

### 2.4 图标与标记

- 不再使用 emoji 作界面图标（原 `🔩` 已移除），改用 Streamlit 原生 Material Symbols（`:material/error:` 等）；
- 状态语义不依赖颜色单一通道：徽章同时有文字（「已就绪」「模型缺失」），热点区域同时有「集中」文字标记与红色边框（满足 UX-003 / UX-038）。

## 3. 各区域改造说明

| 区域 | 改造前 | 改造后 |
|---|---|---|
| 顶部标题 | emoji + 44px 大标题（换行）+ 说明 + 蓝色 info 块 | 25px 单行标题 + 状态徽章行（模型/类别数/锚点规则）+ 说明 + 左侧强调线的规则说明条 |
| 侧栏 | 「检测参数」+ 上传 + 滑块 + 分隔线 + 模型状态 | 增加操作引导 caption、阈值影响说明、模型卡（名称+大小+类别）、「使用提示」三条最佳实践 |
| 主操作 | 全宽「开始检测」按钮，无上下文 | 左按钮 + 右侧显示已选文件名/尺寸/阈值，避免盲操作 |
| 空状态 | 一行 `st.info` 文字 | 卡片式引导：标题 + 说明 + 三步流程（上传 → 设阈值 → 开始检测） |
| 结果概览 | 三个 `st.metric` 默认样式 | 三张 KPI 卡片（标签/大号数值/一句解释），带卡片描边与轻投影 |
| 视图对比 | 两列图片，subheader 直排 | 分区标题带图注（图片尺寸），每张图下有说明性 caption |
| 缺陷构成 | 竖向 `st.bar_chart` + 表格 | 左侧横向条形图（中文类别名更易读）+ 右侧明细表 + 置信度分级说明 |
| 区域分析 | 黄色渐变柱状图 + 文本统计 | 左：**3×3 热力 tile**（含热点标记、冷热图例）；右：品牌蓝柱状图（带轴标签与单位）；下方热点结论 + 归属规则说明条 |
| 导出区 | 两个按钮 | 分区标题 + 用途说明（复核 / 留档） |
| 页脚 | 无 | 数据来源、模型、库版本与边界声明 |
| 全局 | Streamlit 默认 Deploy 工具栏可见 | 隐藏工具栏与主菜单，界面专注 |

### 3.1 九宫格可视化的设计取舍

原方案只有柱状图，读者需要把「区域名 → 数值」在脑中映射回图像位置。改造后增加 3×3 热力 tile：

- 布局与图像的空间方位一一对应，符合「就近原则」；
- 颜色深浅表达密度（Heatmap 的适用场景：density matrix）；
- 柱状图保留，用于**精确读数**（Heatmap 不适合精确读数，引擎建议两者互补）；
- 热点区域双重标记（红框 + 「集中」文字），不依赖颜色单通道。

## 4. 无障碍与规范对照

对照引擎输出的 P0 交付门禁：

| 规则 | 落实方式 |
|---|---|
| UX-001 可访问名称 | 所有交互控件均有可见中文标签，无纯图标按钮 |
| UX-002 对比度 ≥ 4.5:1 | 正文 `#14202E` on `#F6F8FB` ≈ 15.8:1；次要文字 `#5B6B7C` ≈ 5.4:1；均达标 |
| UX-003 不只用颜色表达 | 状态徽章带文字；热点区带「集中」标记；置信度分级同时给数值与文字说明 |
| UX-004 键盘可用 | 全部为原生 Streamlit 控件，保留默认键盘行为 |
| UX-005 焦点可见 | 显式 `:focus-visible { outline: 2px solid var(--brand) }` |
| UX-028 单一主 CTA | 每屏仅「开始检测」为 primary 按钮 |
| UX-037 语义色规范 | green=成功、red=缺陷/错误、amber=警告、blue=信息 |
| UX-038 不用红绿单独配对 | 所有状态均有文字或形状辅助 |
| UX-039 单一强调色 | 仅品牌蓝作强调，红色专属缺陷语义 |
| UX-077 轴标签与单位 | 区域图 Y 轴「缺陷数量（个）」，类别图 X 轴「数量（个）」 |
| UX-079 色盲友好 | 图表单色系，不依赖红绿对比区分数据 |
| UX-080 突出数据不做装饰 | 去除黄色渐变、默认紫框、emoji 装饰 |
| UX-023 移动优先 / 响应式 | `@media (max-width: 1100px / 720px)` 两档断点：KPI 由 3 列→2 列→1 列；图片两列在窄屏自动堆叠 |

### 4.1 已知未覆盖项

- 未做真实屏幕阅读器（NVDA / VoiceOver）走查，仅结构层面保证语义标签；
- 对比度为设计值计算，未用 axe 等工具实测（引擎输出亦为推荐值，非认证结论）；
- Streamlit 的 canvas 表格（`st.dataframe`）对屏幕阅读器支持有限，属框架限制。

## 6. 改造过程中发现并修复的 3 个真实缺陷

| 问题 | 根因 | 修复 |
|---|---|---|
| 区域分析区抛 `NameError: class_names` | `render_zone_analysis` 内部使用该变量但签名缺参数；旧测试从未执行「点击检测」后的路径 | 补参数 + 新增 2 个 AppTest 端到端测试（真实点击按钮跑完整流程） |
| 标注标签被裁到画面外 | 缺陷框贴图片顶边时，标签默认画在框上方越界 | `clamp_label_boxes()` 整体平移进画面，配 3 个边界测试 |
| 标签背景变蓝、与红框不一致 | 自定义标注器 PIL 往返时多做一次 `[:, :, ::-1]`，把 numpy 画的背景色通道反转（白色文字因对称未暴露） | 去掉多余反转，文字改用 `as_bgr()`；新增通道一致性测试 |

## 8. 设计边界

本方案为**可落地的推荐起点**，不是审美终审：

- 配色对比度为设计值计算，生产前需用 axe / WAVE 实测；
- 未做真实用户可用性测试（目标用户为质检人员与算法工程师，建议后续用 5 人小样本走查）；
- 品牌色为工业冷蓝的通用选择，非某企业视觉资产；如对接企业 VI 需替换 `--brand` 系列 token。
