## 0:00–0:50 应用场景与待解决问题

大家好，我演示的项目是**基于 Supervision 的钢材表面缺陷智能检测与区域质量分析系统**。

钢材在轧制、运输和加工过程中，表面会出现龟裂、夹杂、压痕斑块、麻点、
氧化铁皮压入和划痕六类缺陷。人工检查有两个痛点：

1. **效率有限**——一张图里缺陷多的时候，逐个找、逐个记很耗时；
2. **位置不直观**——只记录类别和数量，看不出缺陷集中在产品的哪个区域。

我的项目解决的是"检测结果可视化"和"缺陷空间分布辅助分析"这两个问题。
它是一个验证原型，不接入真实产线，也不做质量合格判定。

## 0:50–1:50 解决方案与核心创新

系统分三层：

- **YOLO** 负责识别缺陷的类别、置信度和边界框；
- **Supervision** 把模型输出统一成 `Detections` 结构，用 `BoxAnnotator` 画框、
  `LabelAnnotator` 标注类别和置信度；
- **核心创新点**：把产品表面划成 3×3 九宫格，用 Supervision 的
  `PolygonZone` 以检测框中心点为锚点判断每个缺陷落在哪个区域，
  统计各区域缺陷数量，指出缺陷集中区域。

创新点表述要准确：这是**应用层的检测结果分析与可视化**，不改变模型精度，
不应说成提高了 mAP。它的价值是把"有多少缺陷"扩展成"缺陷集中在哪"，
为人工复检和工艺排查提供线索。

工程上有一个值得一提的细节：Supervision 的 `LabelAnnotator` 内部用
OpenCV 的 `putText` 渲染文字，不支持中文，类别名会显示成问号。
我通过继承该标注器、只替换文字渲染为 PIL 的 TrueType 渲染解决了这个问题，
保留了它原有的定位和配色逻辑。

## 1:50–3:50 数据、方法与实验设计

**数据**：NEU-DET 钢材表面缺陷数据集，1797 张图片、六类缺陷。
使用的是清理修正版（修正了重复图片和重复标注框，避免数据泄漏）。
按类别分层、固定随机种子 42 划分为训练 1257 / 验证 270 / 测试 270，
即 70 / 15 / 15。

**训练**：YOLOv8n 轻量模型，从 COCO 预训练权重出发，输入 416×416，
40 轮，CPU 训练（i7-12650H）。检测头从 80 类改为 6 类，
预训练权重 349/355 项成功迁移。

**评估设计**：按方案书做了基线与改进的对照——

| 方案 | 处理内容 |
|---|---|
| EXP-01 基线 | YOLO 检测 + 基础目标框展示 |
| EXP-02 改进 | YOLO + Supervision 标注 + 九宫格区域统计 |

两个方案用**同一权重、同一测试集、同一阈值**，所以模型检测指标
（Precision / Recall / mAP）完全一致——这是对照条件的要求。
改进方案的价值用区域统计指标来证明，而不是模型精度。

## 3:50–5:30 实际结果与失败边界

**模型指标**（测试集 270 张，conf=0.25，CPU 推理）：

- Precision **0.736**，Recall **0.486**，mAP@0.5 **0.481**，mAP@0.5:0.95 **0.242**
- 单图耗时 336 ms（含区域统计）

**区域分析指标**——按方案书要求，这些指标必须用**人工标注真值**计算，
不能只拿模型输出自己验证自己。我用 NEU-DET 测试集的人工标注作为真值：

- 区域计数总绝对误差 **503**，单图平均 **1.86** 个缺陷；
- 热点区域命中率 **120 / 270 = 0.444**。

**如实解读这两组数字**：区域误差的主要来源是模型漏检——Recall 只有
0.486，接近一半的真值缺陷没被检出，区域计数自然对不上。热点命中率
0.444 明显高于随机基线（九区域随机约 0.11），说明系统具备一定的
区域分布判别能力，但距离实用还有差距，与模型尚未完全收敛一致。

**失败边界**（主动展示，比被问出来好）：

- 416 输入下细长缺陷（如浅划痕）容易漏检，样例 crazing_101 在
  conf=0.25 下就未检出；有 GPU 条件应该用 640 输入重训。
- 只用缺陷样本训练，没有正常样本，所以系统只输出"检出 / 未检出"，
  **未检出不等于合格**，页面和脚本里都做了明确提示。
- CPU 单图 336 ms，不满足实时产线要求。

## 5:30–6:30 现场原型演示

演示流程：

1. `python check_environment.py` 自检通过；
2. `streamlit run app.py` 启动页面；
3. 从 samples 目录选一张测试集图片上传；
4. 调整置信度阈值，点击"开始检测"；
5. 展示原图与标注结果并排、缺陷统计表；
6. 展示九宫格热力分布与缺陷集中区域；
7. 下载标注图 PNG 和明细 CSV。

命令行版本：`python predict.py --image samples/patches_109.jpg`。

**备份方案**：准备了一段录屏，现场环境异常时播放；
但录屏不能替代可运行程序，主流程是现场跑的。

## 6:30–7:00 项目价值、个人贡献与结语

**价值**：把目标检测能力与 Supervision 的视觉处理能力结合，
形成可操作、可解释、可验证的缺陷分析原型。

**个人贡献**（详见 `docs/contribution.md`）：
数据集整理与划分脚本、模型训练与评估、Supervision 标注与 PolygonZone
区域分析、Streamlit 页面与异常处理、60 个单元测试、全部文档。

**下一步**：完成训练收敛并复测；引入正常样本解决"未检出≠合格"；
用 640 输入重训提升小缺陷召回；接入真实工况图片验证泛化。

**边界重申**：这是公开数据集上的验证原型，实际产线使用还需要
真实工况数据和企业检验标准的验证。

## 预答辩问答准备

| 可能的问题 | 回答要点 |
|---|---|
| 为什么用 Supervision？它做了什么？ | 统一检测结果结构（Detections）、标注可视化（Box/LabelAnnotator）、区域判定（PolygonZone）；它不做训练也不做识别 |
| 九宫格统计会不会把一个缺陷算两次？ | 不会。锚点统一取中心点；分割线上的目标按固定顺序唯一归属；测试集实测区域计数之和 595 = 检出数 595 |
| 区域分析提高了精度吗？ | 没有，也不该这么说。两方案同权重同阈值，模型指标完全一致；价值在空间分布分析 |
| 热点命中率 0.444 是不是太低？ | 高于随机基线 0.11；低的主要原因是模型漏检（Recall 0.486），训练收敛后应改善；同时主动说明这是应用层指标 |
| 为什么 Recall 只有 0.486？ | 416 输入对小缺陷不利 + 训练尚未收敛 + CPU 算力限制；失败样例 crazing_101 已留档 |
| 未检出缺陷是不是合格？ | 不是。只有缺陷样本训练，无正常样本，系统只输出"检出/未检出" |
| 数据集许可？ | 上游 NEU-DET 未声明许可，所以数据不随仓库分发，README 说明获取方式；使用前自行核对 |
| 单图 300ms 能上产线吗？ | 不能，CPU 限制；产线需要 GPU/边缘设备加速，且要接入真实工况 |
| 测试集和训练集有泄漏吗？ | 划分按类别分层、固定种子；所用数据版本已清理 1 张重复图和 2 张近重复图 |
| 你个人做了什么？ | 见 docs/contribution.md，逐项列出，不含未完成内容 |
